# نگهداری و پشتیبانی

## کارهای روزانه، هفتگی و ماهانه

این فهرست همان تعهدات پشتیبانی پروپوزال است.

**هر روز**
- هشدارهای پایش `/api/health` و `/shop`.
- موفق بودن پشتیبان شب قبل (`backups/backup.log`).
- از فاز ۲: پنل ← حسابداری؛ صف «ناموفق» باید خالی باشد.

**هر هفته**
- به‌روزرسانی امنیتی: `git pull`، `pnpm audit --prod`، بازسازی تصاویر Docker.
- مرور لاگ خطاها: `docker compose logs --since 168h api | grep -i error`.

**هر ماه**
- یک بار بازگردانی آزمایشی پشتیبان روی پایگاه داده‌ی جدا.
- گزارش ماهانه از پنل ← گزارش فروش.
- از فاز ۳: پنل ← دستیار تادا؛ مرور گفت‌وگوها و اصلاح ذائقه‌ی محصولات در «منو».

## رسیدگی به اختلال

| نشانه | اول این را ببینید |
|---|---|
| سایت بالا نمی‌آید | `docker compose ps`؛ سپس لاگ `nginx` و `web` |
| سفارش ثبت نمی‌شود | لاگ `api`؛ باز بودن شعبه و «سفارش می‌گیرد» در داشبورد |
| پرداخت برنمی‌گردد | پنل ← سفارش ← تراکنش‌ها؛ وضعیت کد پذیرنده در زرین‌پال؛ `PUBLIC_WEB_URL` |
| پیامک نمی‌رسد | پنل ← تنظیمات؛ اعتبار و قالب کاوه‌نگار؛ جدول `SmsLog` |
| صفحه‌ی بار «در حال اتصال» | تنظیم `proxy_buffering off` برای `/api/staff/orders/stream` در nginx |

سفارش آنلاینی که پرداخت نشود بعد از `PAYMENT_TIMEOUT_MINUTES` خودکار لغو و موجودی و کد تخفیفش آزاد می‌شود. اگر مشتری بعد از آن مهلت پرداخت کند، سفارش دوباره روی بار می‌آید با یادداشت `paid_after_timeout`.

## اتصال به حسابداری

### خروجی CSV
پنل ← حسابداری ← دریافت CSV. هر سطر یک قلم فاکتور است با شماره‌ی فاکتور `TADA-<شماره‌ی سفارش>`؛ مبالغ به ریال.

### وب‌هوک
با `ACCOUNTING_DRIVER=webhook` برای هر سفارش پرداخت‌شده یک درخواست `POST` با بدنه‌ی JSON ارسال می‌شود:

```json
{
  "event": "invoice.created",
  "invoiceNumber": "TADA-1042",
  "orderId": "uuid",
  "issuedAt": "2026-11-23T10:15:00.000Z",
  "branch": { "id": "uuid", "slug": "mollasadra", "name": "ملاصدرا" },
  "customer": { "name": "سارا", "phone": "09121234567" },
  "orderType": "PICKUP",
  "paymentMethod": "ONLINE",
  "paymentRef": "123456789",
  "currency": "IRR",
  "lines": [{ "sku": "product-uuid", "name": "لاته", "quantity": 2, "unitPrice": 2250000, "options": ["شیر جو دوسر"], "lineTotal": 4500000 }],
  "subtotal": 4500000, "discount": 0, "deliveryFee": 0, "total": 4500000
}
```

هدرها: `x-tada-event`، `x-tada-delivery` (شناسه‌ی یکتا برای جلوگیری از ثبت تکراری)، `x-tada-timestamp` و `x-tada-signature: sha256=<hex>` که برابر است با HMAC-SHA256 از `${timestamp}.${body}` با کلید `ACCOUNTING_WEBHOOK_SECRET`.

گیرنده باید امضا را با مقایسه‌ی زمان ثابت بررسی کند، درخواست‌های قدیمی‌تر از ۵ دقیقه را رد کند و با `x-tada-delivery` تکرار را تشخیص دهد. پاسخ 2xx یعنی ثبت شد (اگر بدنه `{"id": "..."}` باشد در پنل نمایش داده می‌شود). خطا یا پاسخ دیگر تا ۱۰ بار با فاصله‌ی افزایشی (۲ دقیقه تا ۶ ساعت) تکرار می‌شود و بعد در پنل «ناموفق» با دکمه‌ی ارسال دوباره می‌ماند.

نمونه‌ی بررسی امضا در Node:

```js
import { createHmac, timingSafeEqual } from 'node:crypto';
const expected = 'sha256=' + createHmac('sha256', SECRET).update(`${req.headers['x-tada-timestamp']}.${rawBody}`).digest('hex');
const ok = expected.length === sig.length && timingSafeEqual(Buffer.from(expected), Buffer.from(sig));
```

برای نرم‌افزارهایی مثل هلو، سپیدار، محک یا حسابفا، یک مبدل کوچک این JSON را به فرمت API یا فایل ورودی همان نرم‌افزار تبدیل می‌کند. ارسال به سامانه‌ی مودیان از راه همان نرم‌افزار حسابداری انجام می‌شود.

## دستیار با مدل زبانی

`LLM_BASE_URL` هر نقطه‌ی پایانی سازگار با `chat/completions` و فراخوانی ابزار است. پیشنهاد: یک مدل متن‌باز روی سرور خودتان (vLLM یا Ollama)، تا داده‌ی مشتری از سرور بیرون نرود. هر مدلی که قوانین استفاده‌اش اجازه می‌دهد قابل استفاده است. بدون این تنظیم، دستیار در حالت هدایت‌شده کامل کار می‌کند.
